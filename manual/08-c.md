# Capítulo 8: Intervención desde C/C++ mediante GObject Introspection

> Este capítulo es opcional. No necesitas escribir C para completar el proyecto. Su objetivo es que sepas qué es posible, qué no y cuándo conviene quedarse en GJS.

## Qué vas a aprender

- Entender cómo GJS consume bibliotecas escritas en C.
- Reconocer qué puede hacer una biblioteca nativa que GJS no puede hacer por sí mismo.
- Conocer el flujo de trabajo de una librería GObject con GIR y typelib.
- Entender las anotaciones de GObject Introspection.
- Evaluar los riesgos de cargar código nativo dentro del shell.
- Decidir cuándo una extensión debe quedarse en GJS.

Al final del capítulo, podrás explicar por qué la mayoría de las extensiones no necesitan C y qué pasos seguiría una biblioteca nativa.

## Antes de empezar necesitas

- Haber completado los capítulos 1 a 7.
- Entender qué es una extensión, un módulo ESM y el ciclo `enable()` / `disable()`.
- Saber que el shell puede fallar si una extensión lanza una excepción.

## El concepto, con una analogía

Una biblioteca en C es como una máquina industrial. GJS no puede usar la máquina directamente: necesita un manual de instrucciones y un adaptador. **GObject Introspection** es ese manual: describe las funciones, los tipos y la propiedad de los datos. El **typelib** es la versión empaquetada del manual que GJS puede leer.

Una extensión que importa una biblioteca GI es como un operador que lee el manual y usa la máquina. Si el manual está mal escrito o la máquina cambia, el operador falla.

### 8.1. El modelo de GObject Introspection

#### 8.1.1. Cómo GJS accede a librerías C: anotaciones GI y typelib

GJS no puede llamar a cualquier función C. Solo puede usar bibliotecas que estén basadas en GObject y que tengan anotaciones de GObject Introspection. El proceso es:

1. La biblioteca define clases y funciones con GObject.
2. El código se anota para indicar tipos, propiedad de la memoria y valores nulos.
3. Una herramienta genera un archivo **GIR** (XML con la descripción).
4. Otra herramienta genera un **typelib** (formato binario que GJS lee).
5. GJS importa el typelib con `gi://NombreDeLaBiblioteca`.

La anotación `(transfer none)` indica que la función no transfiere la propiedad del valor: quien llama no debe liberarlo. `(transfer full)` indica que sí transfiere la propiedad. Una anotación incorrecta puede provocar fugas de memoria o bloqueos.

**Errores posibles en este bloque:** este bloque es una explicación del modelo, no un programa. No produce errores por sí mismo. Si el typelib no está en la ruta de búsqueda, GJS no puede importar la biblioteca.

#### 8.1.2. La limitación práctica: GJS consume librerías basadas en GObject, no código C arbitrario

Una función C suelta, sin GObject ni anotaciones GI, no se puede importar directamente desde GJS. Para usarla necesitas:

- Envolverla en una clase o función GObject.
- Añadir las anotaciones de GI.
- Generar el GIR y el typelib.
- Instalar el typelib donde GJS lo encuentre.

No puedes tomar un archivo `.so` cualquiera y escribir `import MiLibreria from 'gi://MiLibreria'` sin ese trabajo previo.

**Errores posibles en este bloque:** este bloque es una explicación, no un programa. No produce errores por sí mismo. El síntoma de intentar importar una biblioteca sin typelib es un error de carga del recurso GI.

### 8.2. Qué se puede lograr desde C/C++ que no es posible (o es difícil) en GJS puro

#### 8.2.1. Librerías con requisitos de rendimiento intensivo

C puede ser útil para:

- Procesamiento de imágenes o audio en tiempo real.
- Cálculos numéricos intensivos.
- Compresión o criptografía de alto rendimiento.
- Reutilizar una biblioteca existente que ya está escrita en C.

Para una extensión que muestra el clima o un precio, GJS es suficiente. Para un procesamiento que bloquea el shell, una biblioteca nativa puede ayudar, pero también puede introducir fallos difíciles de depurar.

#### 8.2.2. Integración con APIs de bajo nivel del sistema no expuestas por GObject Introspection

Algunas APIs del sistema no tienen typelib. En ese caso, C puede acceder a ellas y exponer una interfaz GObject. Ejemplos:

- Llamadas a ioctls o interfaces del kernel.
- Bibliotecas de hardware sin GObject.
- Funciones de una biblioteca propietaria.

Esta integración es avanzada y queda fuera del alcance del proyecto. El manual no la necesita.

#### 8.2.3. El caso de Mutter: `GnomeShellPlugin` como punto de entrada C del shell

`GnomeShellPlugin` es un plugin nativo de Mutter, no una extensión de GNOME Shell. Se carga en el compositor y puede modificar el comportamiento de Mutter a un nivel que una extensión ESM no alcanza. No se empaqueta como una extensión de `~/.local/share/gnome-shell/extensions/` ni se publica en extensions.gnome.org como una extensión normal.

Este capítulo no enseña a escribir un plugin de Mutter. Si necesitas ese nivel de intervención, es un proyecto distinto del proyecto de este manual.

**Errores posibles en este bloque:** este bloque es una explicación, no un programa. No produce errores por sí mismo. El error conceptual más común es confundir un plugin de Mutter con una extensión de GNOME Shell.

### 8.3. Escribir una librería GObject consumible desde GJS (flujo de trabajo)

#### 8.3.1. Anotaciones GI en cabeceras C

El flujo comienza con una biblioteca GObject. La cabecera declara:

- El tipo GObject y su función `get_type()`.
- Las funciones públicas.
- Las anotaciones de propiedad, nulabilidad y transferencia.
- Las señales y propiedades, si existen.

Las anotaciones se escriben en comentarios de documentación que `g-ir-scanner` interpreta. Por ejemplo, una función que devuelve un texto propiedad de la instancia se anota con `(transfer none)`. Una función que devuelve un texto que el llamador debe liberar se anota con `(transfer full)`.

Si usas C++, expón una interfaz C compatible con GObject. Las anotaciones GI se aplican a esa interfaz C, no directamente a las clases de C++.

**Errores posibles en este bloque:** este bloque es una explicación del flujo, no un programa. No produce errores por sí mismo. Una anotación incorrecta puede causar fugas o liberaciones dobles.

#### 8.3.2. Generación de GIR y typelib con Meson (`gnome.generate_gir`)

Meson es un sistema de construcción. La función `gnome.generate_gir` genera el GIR y el typelib a partir de la biblioteca y la cabecera.

El flujo típico es:

1. Declarar las dependencias de GLib y GObject.
2. Compilar la biblioteca compartida.
3. Llamar a `gnome.generate_gir` con el nombre del espacio de nombres, la versión, las fuentes y la cabecera.
4. Instalar el typelib y la biblioteca.
5. Añadir la ruta del typelib a `GI_TYPELIB_PATH` si se prueba sin instalar.

En un sistema Fedora necesitas las herramientas de desarrollo de GLib, GObject Introspection, Meson y Ninja. Este capítulo no compila una biblioteca; puedes comprobar si tienes las herramientas con:

```bash
pkg-config --modversion glib-2.0
```

**Errores posibles en este bloque:**

**Error 1: `Package glib-2.0 was not found in the pkg-config search path`.**
- **Ubicación:** terminal.
- **Síntoma:** `pkg-config` no encuentra GLib.
- **Causa:** faltan las cabeceras de desarrollo de GLib o `PKG_CONFIG_PATH` no está configurado.
- **Corrección:** instala el paquete de desarrollo de GLib de tu distribución. Después de corregir, el comando devuelve una versión.

**Error 2: `bash: meson: orden no encontrada...`.**
- **Ubicación:** terminal.
- **Síntoma:** no puedes ejecutar la construcción.
- **Causa:** Meson no está instalado.
- **Corrección:** instala Meson y Ninja desde el gestor de paquetes de tu distribución. Después de corregir, el comando está disponible.

#### 8.3.3. Importación desde GJS: `import MiLibreria from 'gi://MiLibreria';`

Cuando el typelib está instalado y visible, GJS puede importarlo:

```javascript
import MiSaludo from 'gi://MiSaludo';
```

> **Qué hace este bloque:** importa el espacio de nombres `MiSaludo` desde el typelib. `MiSaludo` debe existir en `GI_TYPELIB_PATH` o en una ruta de introspección del sistema. La importación no ejecuta la biblioteca; únicamente la pone a disposición del archivo.

**Errores posibles en este bloque:**

**Error 1: `Typelib file for namespace 'MiSaludo' (any version) not found`.**
- **Ubicación:** línea del import.
- **Síntoma:** la extensión no carga.
- **Causa:** el typelib no está instalado o `GI_TYPELIB_PATH` no incluye su carpeta.
- **Corrección:** instala el typelib o añade la ruta. Después de corregir, el import funciona.

**Error 2: `ImportError: Unable to load file from: gi://MiSaludo`.**
- **Ubicación:** línea del import.
- **Síntoma:** el recurso no se encuentra.
- **Causa:** el nombre del espacio de nombres no coincide con el typelib.
- **Corrección:** usa el nombre exacto del espacio de nombres. Después de corregir, el import funciona.

### 8.4. Límites prácticos para extensiones de GNOME Shell

#### 8.4.1. Las extensiones se ejecutan dentro del proceso del shell; agregar código C nativo incrementa el riesgo

Una biblioteca nativa se carga dentro del proceso de GNOME Shell. Si la biblioteca tiene un fallo de memoria, puede cerrar el shell completo. No hay un proceso separado que aísle el error.

Riesgos principales:

- Un fallo de segmentación cierra el escritorio.
- Una fuga de memoria afecta a toda la sesión.
- Un ABI incompatible falla al cargar.
- La biblioteca puede depender de una versión concreta de una librería del sistema.
- El empaquetado y la revisión de EGO se complican.

#### 8.4.2. Cuándo es mejor una extensión GJS pura y cuándo justificar una librería externa

| Situación | Recomendación |
| :--- | :--- |
| Interfaz del panel, menús, CSS | GJS puro |
| Peticiones HTTP, JSON, temporizadores | GJS puro |
| Uso de una biblioteca que ya tiene typelib | Importar desde GJS |
| Cálculo intensivo que bloquea el shell | Biblioteca nativa, si está justificada |
| API de bajo nivel sin GI | Biblioteca nativa envolvente |
| Plugin de Mutter | Proyecto separado, fuera de este manual |

Para el proyecto de este manual, GJS es suficiente. No añadas C para mostrar un botón, una notificación o un precio.

## Errores de integración del capítulo

### Error 1: confundir una extensión con un plugin de Mutter

**Síntoma:** intentas cargar un plugin de Mutter como si fuera una extensión ESM.

**Causa:** `GnomeShellPlugin` pertenece al compositor, no al sistema de extensiones de usuario.

**Corrección:** usa una extensión GJS para el panel y las APIs del shell. Un plugin de Mutter es otro proyecto.

### Error 2: importar una biblioteca sin typelib

**Síntoma:**

```text
Typelib file for namespace 'MiSaludo' (any version) not found
```

**Causa:** el typelib no está instalado o no está en `GI_TYPELIB_PATH`.

**Corrección:** instala el typelib o añade su ruta. Después de corregir, el import funciona.

### Error 3: anotación de transferencia incorrecta

**Síntoma:** fugas de memoria, liberaciones dobles o bloqueos después de varias llamadas.

**Causa:** una función devuelve un valor con `(transfer full)` pero el llamador no lo libera, o se anota `(transfer none)` y el llamador lo libera.

**Corrección:** revisa la propiedad del valor y corrige la anotación. Después de corregir, la memoria se gestiona correctamente.

### Error 4: el shell se cierra al cargar la biblioteca

**Síntoma:** el escritorio se reinicia o se cierra la sesión.

**Causa:** un fallo nativo, un ABI incompatible o una dependencia faltante.

**Corrección:** prueba la biblioteca fuera del shell, revisa las dependencias y usa una versión compatible. Después de corregir, la carga es estable.

## Respuestas razonadas

1. GObject Introspection es el sistema que describe bibliotecas C basadas en GObject para que otros lenguajes, como GJS, puedan usarlas. Genera una descripción de tipos, funciones y propiedad de la memoria.

2. Un typelib es el archivo binario generado a partir de la descripción GIR. GJS lo carga cuando escribes `gi://Nombre`. Sin typelib, el espacio de nombres no existe para GJS.

3. `(transfer none)` indica que la función no transfiere la propiedad del valor. El llamador no debe liberarlo; el objeto que lo devolvió sigue siendo responsable.

4. Porque GJS únicamente conoce las bibliotecas que tienen un typelib de GObject Introspection. Una función C suelta no tiene metadatos de tipos ni de memoria, así que GJS no sabe cómo llamarla.

5. La justificarías para un cálculo intensivo, una API de bajo nivel sin GI o una biblioteca existente que ya tiene typelib. No la justificarías para una interfaz, una petición HTTP o una operación que GJS ya resuelve.

6. Porque un plugin de Mutter se carga en el compositor y modifica Mutter. Una extensión de GNOME Shell es un módulo ESM que se carga en el sistema de extensiones del shell. Son mecanismos distintos.

## Soluciones de los ejercicios

### Solución del reproductivo

1. Un typelib es el archivo binario que describe una biblioteca GI para GJS.
2. `(transfer none)` significa que el llamador no recibe la propiedad del valor y no debe liberarlo.
3. GJS necesita metadatos GI; un `.so` sin typelib no los tiene.
4. Fallo de segmentación, fuga de memoria y conflicto de ABI.
5. Mostrar un botón: GJS. Procesar imagen en tiempo real: C. Leer un precio: GJS.

**Errores posibles en este bloque:** este bloque son respuestas conceptuales, no un programa. No produce errores de ejecución. Si una respuesta no coincide, vuelve a la sección correspondiente.

### Solución del aplicativo

### Solución del creativo

- Una clase `MiSuma` que hereda de `GObject`.

- Una anotación de transferencia para los valores devueltos, si los hubiera.
- Un `meson.build` con `gnome.generate_gir`.
- Un import `import MiSuma from 'gi://MiSuma';`.

**Errores posibles en este bloque:** este bloque es un diseño, no un programa. No produce errores de ejecución. Si el diseño no menciona GIR, typelib o `gi://`, vuelve a la sección 8.3.
